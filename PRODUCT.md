# OpenFinacle

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Customers managing their banking, and branch officers and independent approvers handling the same relationship. Older customers need comfortably readable screens.

The public landing is a capability-led marketing magazine for bank/product decision-makers and people exploring how far AI-assisted rebuilding can go. Varied editorial sections, actual synthetic screens and short paragraphs introduce the experience and path to production. One comparison section is capped at ten selected areas. Detailed capabilities, roadmap and build-method inner pages carry deeper explanations. The interactive build recipe is central: talent mix, founder-supplied INR pay scales, scope, AI-assisted/AI-first allocation, dated USD API usage and explicitly assumed impact/ROI. No simulated financial product, scope estimate, token budget or return is presented as accepted production capability.

## Product Purpose

Reconstruct customer internet banking and branch workflows in a working demonstration with persistent, synthetic data. Specifications under `specs/006-reference-banking-experience/` own capability requirements and evidence boundaries.

## Capabilities and Constraints

Fineract owns balances and financial postings. Explicit simulated products and workflow records persist separately. Preserve maker-checker, uncertainty, review, idempotency, recovery, and role boundaries. Do not fabricate charts, financial performance, or completed capabilities. Never include real banking information. The repository remains private.

## Brand Commitments

OpenFinacle. The user requests a colorful, modern, professional interface with Xero and Payoneer as public visual references. Retain clear banking terminology and recognizable controls.

## Accessibility & Inclusion

Comfortable large text by default. The user removed the separate extra-large text button on18October2026; retain browser zoom and enlarged-text reflow support. Generous controls, strong contrast, keyboard operation, responsive reflow, and readable financial values take priority over decorative density.

Portal screens have stable bookmarkable links, including unavailable menu destinations. Links restore the currently saved customer session; they do not select customers or grant roles. Back/Forward only navigates. Card, deposit, service and embedded/standalone planning sections retain their selected destination on reload. Financial original-outcome recovery stays independent of URL state.
